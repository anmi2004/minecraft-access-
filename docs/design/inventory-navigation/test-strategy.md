# 背包导航测试策略

> 2026-10-25：纯逻辑测试、完整离线构建和双加载器客户端初始化已完成。真实合成台 GameTest 与完整屏幕阅读器人工矩阵尚待执行。

## 目标

测试必须证明：

1. 原背包操作没有回归。
2. 导航阶段不移动真实鼠标。
3. 焦点变化立即产生正确朗读。
4. 动作手势发生时才同步光标。
5. 同步一定发生在鼠标 press 之前。
6. 配方按钮当前变体变化后及时朗读。
7. 不可见配方按钮不会成为焦点。
8. 所有 GUI 和光标操作都在客户端线程。
9. `J/L` 横向越界只报告没有项目。
10. `I/K` 纵向越界触发自动翻页。
11. 分类切换朗读实际可见分类的名称和位置。
12. 配方书等普通控件获得焦点后快捷键仍有效。
13. 文本框正在接收输入时快捷键不会吞掉字符。

单纯构建成功不能证明任何一条。

## 测试层次

### 1. 纯单元测试

把模型、焦点和动作状态机与 Minecraft 全局状态隔离。

适合测试：

- 方向导航。
- 组内和跨组边界。
- 目标 ID 稳定性。
- 可见性过滤。
- 焦点恢复。
- 朗读文本格式。
- 去重键。
- 快速点按、长按和焦点失效的动作状态转换。

建议测试替身：

- `MouseActionSink`：记录 move、press、release。
- `NarrationSink`：记录 text、interrupt、顺序。
- `InventoryScreenModelFixture`：构造真实槽位、配方和控件目标。

断言顺序示例：

```text
move(target)
press(left)
release(left)
```

不得只看最终集合，否则无法发现“先点击后移动”的回归。

### 2. Minecraft 集成测试

使用真实 `AbstractContainerScreen`、`Menu` 和原版鼠标处理验证：

- 移动到槽位后，`hoveredSlot` 指向正确槽位。
- press 和 release 被当前 Screen 消费。
- 原版点击后，菜单状态符合预期。
- Screen 结构更新后焦点仍有效。

### 3. Fabric Client GameTest

Controlify 已证明 Fabric Client GameTest 可以验证配方书分类和翻页。Minecraft Access 可增加等价测试：

- 创建测试世界和合成台。
- 解锁足够配方，使配方书至少有两页和多个分类。
- 用虚拟输入移动逻辑焦点。
- 捕获朗读调用和鼠标操作顺序。
- 验证配方书结果按钮的点击产生原版配方放置请求。

### 4. 人工屏幕阅读器验收

自动化无法判断语速、打断和声音反馈是否舒适。必须覆盖真实屏幕阅读器。

## 核心状态测试

### 导航不移动鼠标

测试步骤：

1. 记录 `MouseActionSink`。
2. 连续执行上下左右和组切换。
3. 断言没有 `move`、`press` 或 `release`。
4. 断言每个有效焦点变化都有朗读。

验收：

- 硬件鼠标坐标不变。
- 逻辑焦点改变。
- 朗读顺序与导航顺序一致。

### 普通槽位朗读

测试数据：

- 空槽。
- 数量为 1 的物品。
- 数量大于 1 的物品。
- 带额外工具提示的物品。
- 可放置和不可放置于当前槽位的携带物。

验收：

- 文本包含区域、数量、名称和有效附加信息。
- 不重复名称。
- 不含空行或未解析格式化码。

### 动作前同步光标

测试步骤：

1. 逻辑焦点移到已知槽位。
2. 模拟 `[` 按下。
3. 让动作桥执行一个客户端 tick。
4. 模拟 `[` 释放。

断言严格顺序：

```text
move(cursor -> focused target)
press(left)
release(left)
```

额外测试：

- key down 和 key up 在同一 tick。
- key down 后焦点在同步前失效。
- key down 后 Screen 关闭。
- 长按超过一个 tick。
- 目标被物品变化替换但槽位 ID 仍相同。

预期：

- 同 tick 点按仍完整执行 move、press、release。
- 焦点失效时取消操作并给出简短提示。
- Screen 关闭后不发送操作。
- 长按不在错误位置重复触发。

### 焦点恢复

场景：

- 容器内容刷新但槽位仍在。
- 配方搜索导致目标消失。
- 配方翻页。
- 分类切换。
- 可制作过滤导致目标消失。
- 自动打开或关闭配方书。

验收：

- 原目标存在时保持。
- 消失时按文档中的最近有效目标规则恢复。
- 不选择不可见目标。
- 普通列表刷新不自行执行跨组切换。

### 屏幕焦点与文本输入

输入路由测试：

1. 模拟配方书组件获得焦点。
2. 触发 `Shift+C`，断言组从配方切换到合成输出。
3. 聚焦配方书搜索框并模拟字符输入。
4. 断言背包快捷键返回未处理，且字符仍由原版文本框消费。
5. 退出搜索框后再次触发 `Shift+C`，断言组切换恢复。

纯逻辑测试用 `InventoryScreenInputTest` 覆盖普通控件焦点、可消费输入的 `EditBox` 和不可消费输入的 `EditBox`。真实 GUI 测试必须再次验证 Kuma 的 `ignoreScreenFocus()` 注册确实生效，因为单元测试不能替代 Kuma 分发器。

## 配方书测试

### 可见按钮过滤

构造最后一页少于 20 个结果的配方书。

断言：

- 模型只包含 `button.visible == true` 的目标。
- 导航到最后一个可见目标后不再进入空白目标。
- 每页目标数量与界面一致。

### 显式分页快捷键

复用 Controlify 的测试思路：

1. 等待配方书可见且总页数大于 1。
2. 向前翻页，等待 `currentPage == 1`。
3. 向后翻页，等待 `currentPage == 0`。
4. 每页刷新后断言焦点仍属于可见按钮。

### 横向边界不翻页

测试步骤：

1. 聚焦任意页最左列可见配方。
2. 按 `J`。
3. 聚焦最右列可见配方。
4. 按 `L`。

验收：

- 朗读“左侧没有项目”或“右侧没有项目”。
- `currentPage` 不变。
- 当前焦点不变。
- 不产生鼠标 move、press 或 release。
- 配方模型不重建。

即使当前是最后一列和最后一页，`L` 也不能翻页或换行。

### 纵向边界自动翻页

准备至少两页配方。

向下测试：

1. 焦点放在第一页最后一行的第 3 列。
2. 按 `K`。
3. 等待翻页和按钮更新。
4. 断言 `currentPage == 1`。
5. 断言焦点位于第二页第一行第 3 列。

向上测试：

1. 焦点放在第二页第一行的第 3 列。
2. 按 `I`。
3. 等待翻页和按钮更新。
4. 断言 `currentPage == 0`。
5. 断言焦点位于第一页最后一行的第 3 列。

边界测试：

- 最后一页底行按 `K`：不循环，朗读最后一页。
- 第一页顶行按 `I`：不循环，朗读第一页。
- 目标列不存在：选择目标行最近的可见配方。
- 纵向自动翻页不移动鼠标。
- 显式 `Shift+K/I` 仍可翻页。

### 分类

1. 收集所有可见分类。
2. 从第一个分类切换到下一个。
3. 断言选中分类和配方模型同步更新。
4. 再切回第一个分类。
5. 断言每次切换都朗读名称和 `当前序号/总数`。

分类名称测试：

- 所有原生注册分类有本地化名称。
- `SearchRecipeBookCategory` 有名称。
- 模拟的第三方注册分类通过兼容注册器提供名称。
- 未注册翻译时回退到格式化注册 ID。
- 隐藏分类不进入切换顺序。
- 修改分类顺序不影响名称解析。

### 过滤和搜索

- 切换“仅显示可制作”后刷新目标。
- 输入搜索词后只保留搜索结果。
- 清空搜索后恢复原集合。
- 每次刷新不重复朗读大量旧焦点。

### 同槽多配方变体

必须构造一个按钮包含多个不同结果的情况，例如不同木材木板。

测试步骤：

1. 把逻辑焦点移入该按钮。
2. 断言立即朗读当前 `getDisplayStack()`。
3. 记录当前 `RecipeDisplayId` 和 `ItemStack`。
4. 等待原版 `slotSelectTime` 轮换。
5. 断言下一个客户端 tick 内产生新朗读。
6. 断言没有调用鼠标移动。
7. 断言相同变体在连续 tick 中不重复朗读。

验收：

- 不冻结原版动画。
- 不提前显示尚未轮换的变体。
- 新变体出现后及时朗读。
- 不同木板有不同名称或组件时能被区分。

### 点击配方

1. 逻辑焦点位于配方结果。
2. 按 `[`。
3. 验证光标先到按钮中心。
4. 验证原版按钮收到点击。
5. 验证配方进入合成格或触发原版配方放置流程。

验收：

- 合成结果和材料数量与原版一致。
- 客户端不直接伪造服务端物品状态。
- 光标同步期间的重复 hover 朗读被抑制。

## 原功能回归矩阵

| 场景 | 必测行为 |
|---|---|
| 玩家背包 | 拿取整组、半组、放置、交换 |
| 快捷栏 | 移动、放置、快速移动 |
| 箱子 | 大箱子 54 格、跨组移动 |
| 合成台 | 配方点击、合成格行列朗读、输出槽 |
| 熔炉类 | 输入、燃料、输出、燃料状态 |
| 村民 | 交易选择、输入输出、滚动 |
| 切石机 | 配方滚动、结果朗读 |
| 织布机 | 图案、染料、横幅输入 |
| 铁砧 | 文本框聚焦与退出、输入输出 |
| 砂轮、制图台、锻造台 | 专用组和结果 |
| 创造背包 | 标签页、搜索、滚动、克隆堆叠 |
| 未知模组 Screen | 可见控件和未知槽位兜底 |
| 背包控制关闭 | 原有悬停朗读不被新逻辑破坏 |

每个场景至少验证：

- 能聚焦。
- 能正确朗读。
- 动作手势有效。
- 目标变化后的焦点合理。

## 屏幕阅读器人工矩阵

| 平台 | 检查项 |
|---|---|
| Windows + NVDA/Narrator | 普通槽位、配方变体、快速导航打断 |
| macOS + AVSpeechSynthesizer/VoiceOver 共存 | 配方分类、翻页、物品工具提示 |
| Linux + Speech Dispatcher/Orca 共存 | 普通槽位、长按动作、窗口失焦 |

所有平台还应测试：

- GUI scale 自动、1x、2x、3x。
- 一次快速连续按键。
- 慢速逐项听读。
- 高延迟语音和立即打断。
- 配方书打开、关闭和自动打开。

## 双加载器验收

每个阶段在公共代码完成后运行：

```powershell
.\gradlew.bat :fabric:build :neoforge:build test -x check --offline
```

验收：

- Fabric 和 NeoForge 都加载客户端模块。
- 两项构建都没有直接依赖另一加载器的运行时类。
- 自动翻页、分类 ID、逻辑焦点和鼠标同步在两端使用相同公共实现。
- 只存在于一个加载器的可选分类元数据缺失时，另一端使用 ID 回退。
- 不允许通过复制两套背包控制逻辑实现相同行为。

## 时序与性能验收

在开发构建中使用计数器记录：

- 导航事件到 `NarrationSink` 调用。
- 动作事件到 `MouseActionSink.move`。
- move 到 press。
- 变体变化到朗读。

建议门槛：

- 导航路径移动真实鼠标次数严格为 0。
- 导航到朗读调用小于 50 ms。
- 动作手势到 press 小于 100 ms。
- 变体变化到朗读不超过 1 个客户端 tick。
- 空闲时不在每个 tick 重建完整模型。

测量使用客户端线程时间，不人为 sleep。

## 失败诊断要求

失败日志至少包含：

- Screen 类名。
- 模型版本。
- 目标类型和目标 ID。
- 组索引。
- 配方页码、分类、`RecipeDisplayId`。
- 光标同步状态。
- 朗读键和 interrupt 值。

日志不得输出账号、服务器地址或聊天内容。
